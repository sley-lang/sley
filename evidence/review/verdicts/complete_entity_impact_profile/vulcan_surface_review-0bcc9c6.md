## Findings

**F1 (P3, record)** `crates/sley-query/src/entity_read.rs:470-478`. The `capture_entity_read_selection` doc says "the surviving identity checks re-pin each view" and "Returns the first failing byte-ceiling or identity check." Capture performs no identity check; its only fallible step is `check_byte_payload` (already satisfied during selection) and a `u64::try_from(usize)` that cannot fail on 64-bit. The re-pin actually happens in prepare's views loop (442). The property holds, but the comment misattributes where, and a future maintainer could remove the prepare-side `agree` believing capture covers it. Correct the comment; no code change needed.

**F2 (P4, implementation)** `crates/sley-query/src/entity_read.rs:400-407, 466-519`. The prepare → preflight → reserve → capture order is enforced by convention in `server.rs`, not by the type system: nothing stops a caller from invoking `capture_entity_read_selection` before the reservation. With a single production call site this is acceptable; a reservation token or a capture closure supplied by the caller would make the order structural. Design note, no defect on the current tree.

**F3 (P4, implementation)** `crates/sley-query/src/entity_read.rs` tests. No test counts `view_at` invocations, so a regression that iterates all indices through `view_at` without accounting them would pass the poison test (`non_selected_bodies_are_never_semantically_extracted` detects only semantic extraction or accounted bytes). A `Ctx` carrying a `Cell<usize>` call counter asserting exactly `2 + 2×parameters` (or whatever the settled count is) lookups would pin both the "selected indices only" claim and Ariadne's F5 re-evaluation note. The pointer-equality test also covers only the Version path; the Signature path shares the loop, so this is strength, not coverage.

**F4 (P4, record)** `scripts/check_complete_entity_impact_profile.py:119-147`. `lock_packages` keys by name only; if two versions of one package ever appear in `Cargo.lock` the earlier entry's dependencies are dropped (last wins), which could hide a transitive edge. Today `Cargo.lock` has zero duplicate names (verified), so the check is currently sound; union the dependency lists per name to keep it sound under future lock changes.
