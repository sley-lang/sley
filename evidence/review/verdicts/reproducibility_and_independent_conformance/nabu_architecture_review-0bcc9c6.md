**Classification.** This is a record defect, not an implementation or contract defect. The mechanism is behaving exactly as revision 3 specified: a changed surface must not present an old candidate as current, and a dirty tree must not attest. Nothing in S20-730's code or contract is wrong here, and nothing in the rev-5 delta could have closed it. The delta added four more surface changes (`crates/sley-protocol`, `crates/sley-query`, `crates/sley-repo` entity-read files), so the gap is not shrinking on its own.

**Why it still blocks PASS.** The finding register reads a PASS as `declares_no_open_p0_p1_p2`. A PASS on a section whose own `make quick` gate fails at the reviewed commit would be a false declaration, and the Greyforge in-flight repair rule forbids passing a validation gate with an unresolved condition. Severity stays P1 for continuity with the prior round; it is the same finding carried, not a new one.

**Why it is not a lane conflict that needs a rule change.** The constraint pins two things: the RW-080 files stay where they are, and the clean-tree predicate stays whole-tree. Neither has to move. A detached linked worktree at `0bcc9c6` (`git worktree add --detach <path> 0bcc9c6`) is clean by construction: `git status --porcelain` there is empty because the untracked slices live only in the main checkout. Running `make release-candidate-smoke` in that worktree mints an attestation for commit `0bcc9c6` with `working_tree_clean: true`; the refreshed `reproducibility-report.json` is committed on a branch from the worktree and fast-forwarded to `main` (a records-only commit touching no surface file, so the freshness diff is zero). Disk hygiene requires `git worktree remove` afterward. I did not do this: it is a build, a commit, and outside this review's read-only authority. It is the recommended cure and needs the integrator or operator to execute it.

**Alternative I do not recommend.** Narrowing the S20-720 predicate to surface-scoped untracked files would also unblock, but the whole-tree rule is the conservative guard against hidden build inputs the surface list does not name (`.cargo/config.toml`, environment-read `build.rs`), and it is S20-720's contract, not S20-730's.
