## Independently re-derived claims

**Paging predicate at the boundaries (engine).** `page_items` (:1485-1500): `total` is the complete count before the cursor filter; the filter is strict `key > after`; `truncated = remaining_count > limit`; `RequiredFactOmitted` iff truncated and continuation refused; `take = min(limit, remaining)`. So at `remaining == limit` the page is served untruncated, at `remaining == limit + 1` it is truncated (or refused). `next_after` is the last returned key iff truncated, in every arm (:1338, :1364, :1390, :1416, :1442, :1468). The spec's `truncated = returned < items after the cursor` is the same predicate (returned = min(limit, remaining) < remaining iff limit < remaining). A cursor past the end yields `returned 0, truncated false, total exact` (page-roots-2 / page-entry-points-2 pin this), which the revision 6 standalone rule correctly refuses to call complete because `after != None`.

**Cursor typing and single-key classes.** `validate_cursor` (:722-728) runs in both entry points before `verify()` and before any paging; `key_tag` (:402-414) maps 1/2/3/9 to `None` (any cursor is `ContinuationInvalid`), 11 to root, 12/13 to edge, else entity. The `Entities` arm with `key_tag() == None` (class 9) refuses `count > max_returned_entities` with `RequiredFactOmitted` regardless of `allow_continuation` (:1307-1320), matching "single-key classes never page". Precedence in `build_root_query_request` is limits → arm → shape → cursor → binding (items 1-5); in `execute_root_query` limits → arm → shape → cursor → identity drift → binding → snapshot mismatch → presence → applicability (items 1-8). Unchanged from 43f2f5b.

**Revision 6 section 3 page-set rule versus engine and consumer.** Under identical requests except `after`, unique canonical keys, strict `>`, and `next_after = last returned key`: page 1 (`after = None`) returns keys k1..kL; page 2 filters `> kL`; the union is the complete result and `sum(returned) = total` holds exactly; every page recomputes the same complete result so `total_count` is constant; a truncated page always carries a cursor, so "every page but the last truncated" and "last page untruncated with `next_after = None`" are exactly the engine's chain termination.
