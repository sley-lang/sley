## Design brief

Contract: `docs/spec/SMP1.md` revision 1, ADR-0032, stage checker
`scripts/check_smp1_contract.py`.

- Frames are length-prefixed SCB1 standalone envelopes under one contract
  tag 400 and the `sley2.protocol-frame.v1` domain registered by S20-410;
  the hello is frame kind 4 (revision 2, because the epoch registry keys
  digest domains uniquely per contract); the negotiated `max_frame_bytes`
  is checked before allocation.
- Derived negotiation: greatest common version, first common epoch, minimum
  limits, intersected methods and features; the selected profile is
  digested under `sley2.protocol-handshake.v1`; `PROTOCOL_DOWNGRADE` is
  exact.
- Session-scoped strictly increasing request identifiers;
  `PROTOCOL_REQUEST_ID_CONFLICT` before execution; `SESSION_*` semantics
  stay with S20-330.
- Forty-one frozen method tags in six families, each naming the frozen
  contract that owns its bodies; reserved methods fail with a versioned
  reason.
- Bounded context copied from the owning response on every reply; no
  partial bodies; a failure envelope that preserves owner codes.
- Codes 40000 through 40011.

## Open questions for the reviews

- Whether the frame should carry the negotiated `ProtocolHandshakeId`
  explicitly on every request rather than only at `session.open`.
- Whether `workspace.create` and `workspace.open` belong to S20-390's
  repository surface or to S20-330's session authority.
- Whether the JSON bridge's integer rule (decimal strings above 2^53) is
  the right declared encoding for S20-420.

## Answers at revision 11

- *Handshake id on every request?* No. The session binds the handshake
  at `session.open` (contract section 2), and every later frame names
  `protocol_version` checked against the selection; repeating the
  32-byte identity widens every frame and proves nothing extra.
- *`workspace.create`/`workspace.open` owner?* The bodies stay S20-390's;
  the session-to-workspace binding is S20-330's (contract section 3),
  with the genesis exemption stated: the two methods may travel without
  a session only while no accepted head exists.
- *JSON integer rule?* Kept conditional (contract section 8): small
  integers render as JSON numbers so the frozen S20-420 vectors and
  field decoders keep one agreed shape, large integers never lose
  precision, and JSON stays non-canonical debug rendering.
