## Method

1. Enumerated every `"sley2.*"` string in `crates/`, `scripts/`, `oracle/`, `conformance/`, `bench/` and every `SLEY????` framing magic, then followed each to the function that builds the preimage and calls `derive` (or SHA-256 / keyed BLAKE3).
2. Split the inventory into four groups: A kernel (sley-id, scb1, state-root, txn, schema, policy, mutate), B execution and evidence (ssmc, vm, conformance, bootstrap, host ABI, bench chains), C repository, query, protocol, adapter (repo, query, protocol, adapter), D qualification and report record digests (scripts only).
3. For each identity filled the ten section 7 fields and the fifteen section 8 hygiene items, citing the owner function, the owning spec, and the frozen vector.
4. Ran the checkers that arbitrate divergence: `scripts/check_required_contract_index.py` PASS (50 derived domains, 0 unregistered), `scripts/check_oracle_independence.py` PASS (26 python sources), the independent oracles for state-root, schema-epoch, pack, exchange, merge, semantic-comparison, smp1, context-capsule, vm-extended, root-backed-query, complete-root-index-snapshot (all PASS at `560a5f16`), the thirteen Group B python checkers (exit 0), `check_bootstrap_capability.py` PASS, and a scratch SHA-256 of both `conformance/bootstrap-profile/v*/profile.json` files against the Rust constants (see AT-HH-01).
5. Checked how each independently maintained definition is bound to the frozen fixture on BOTH sides (Rust and Python), since section 7 requires a checker that fails on divergence.

## Empirical facts that shape the findings

- Non-minimal varint rejection is one implementation: `ScbValueCursor::read_uvar` at `crates/sley-scb1/src/lib.rs:603-608`, used by every SCB1 envelope decoder; frozen negative vector `conformance/scb1/v1/rejected.json`. Local readers in state-root (`lib.rs:781`) and policy (`lib.rs:2473`) emit the same `SCB_VARINT_NON_MINIMAL` code and have their own tests (`state-root/lib.rs:1243-1250`, `policy/lib.rs:3087-3094`).
- Every stored envelope decoder checks end of input after the trailer and refuses `SCB_TRAILING_BYTES` before exposing a digest (kernel: `object.rs:300-323`, `state-root/lib.rs:1127-1130`, `txn/codec.rs:1361-1371`, `schema/lib.rs:1444-1462`, `policy/lib.rs:2956-2959`, `candidate_result.rs:1293-1304`; repo: `lib.rs:666-669`, `exchange.rs:668-673`, `merge.rs:2191-2194`, `compare.rs:1361-1364`; protocol `lib.rs:1146-1149`; image `rw070_host_abi_freeze.rs:1065-1068`).
- The divergence arbiter is the committed fixture, bound on both sides. Python side: `make conformance` (`Makefile:116-148`) runs the independent oracle over every frozen family. Rust side: `make quick` runs `scripts/generate_<family>_fixtures.py --check` for transaction-receipt, candidate-result, repository-exchange, context-capsule, merge, semantic-comparison, root-backed-query, smp1, smp1-json-bridge, vm-extended, complete-root-index-snapshot, complete-entity-impact, release-demo and bootstrap-profile (`Makefile:19-52, 94-100`); each reruns the crate's `emit_*_for_fixture_refresh` test through `cargo test` and fails if the regenerated bytes differ from the committed file. Rust consumes the fixture directly for scb1 (`crates/sley-scb1/tests/conformance.rs:45,82`), mutation-value and mutation-candidate (`crates/sley-mutate/src/codec/fixture_tests.rs:11-18`), smp1 and smp1-json-bridge (`crates/sley-json-bridge/src/tests.rs:10`, `lib.rs:35`, `crates/sley-cli/tests/cli.rs:21`), and pins the frozen hex in source for state-root (`crates/sley-state-root/src/lib.rs`, root `d3914cbf...` and epoch `a7fcf97a...`) and schema-epoch (`crates/sley-schema/src/lib.rs`, `ae5b2357...`). The standalone repository-pack accepted vector has no direct Rust binding (`7a1e139c...` is pinned only in `scripts/check_repository_pack_spec.py:55-68`), but the exchange fixture embeds the exact stored pack bytes as field 2 and is regenerated from Rust under `--check`, so a Rust pack preimage change fails `make quick` through `generate_repository_exchange_fixtures.py`. The group files' remark that Rust drift "surfaces only at fixture refresh" is therefore superseded; see AT-IG-02.
- The registry drift check `scripts/check_required_contract_index.py:96-107` scans `crates/**/*.rs` only. Twenty-two further `sley2.*` strings live only in `scripts/`, `bench/` and `conformance/*.json`. Fourteen are JSON `contract` labels inside qualification records whose digest is `sha256(json.dumps(record, indent=2, sort_keys=True) + "\n")` with the digest field excluded from its own preimage (`scripts/build_decision_dossier.py:55-60`, `build_finding_register.py:84-88, :411`, `build_release_provenance.py:75`); four are SHA-256 evidence-chain prefixes with a NUL terminator (`bench/sley2/runner.py:66-67`, `bench/raw/runner.py:30-31`); one (`sley2.host-boundary.v1`) is the charter's own contract label (`host-boundary.json:57`); the rest are marker labels. ## 1. Per-identity records (all ten section 7 fields)

Records are grouped A (kernel), B (execution and evidence), C (repository, query, protocol, adapter). Group D (qualification records) is in the header above. Notation is stated at the head of each group.


### Group A: kernel identities

Notation: `H(D, p) = BLAKE3-256(D || p)` where `D` is the exact ASCII domain from `crates/sley-id/src/lib.rs:89-123` and `p` the preimage. `uvar` is the SCB1 minimal varint; `len(x) = uvar(byte_length(x))`. All 32-byte identities are `sley-id` newtypes; only `sley-id` knows the domain table (`digest()` at `crates/sley-id/src/lib.rs:128-133`, no public arbitrary-domain API).

Shared facts used below:

- SCB1 standalone envelope: `"SLEYSCB1" || uvar(1) || uvar(contract_tag) || SchemaEpochId[32] || len(payload) || payload`, digest trailer outside its preimage (`docs/spec/SCB1.md` section 2).
- Non-minimal varint rejection is centralised in `sley-scb1` (`ScbValueCursor::read_uvar` -> `Reader::read_uvar_width`, `crates/sley-scb1/src/lib.rs:603-608`; error `SCB_VARINT_NON_MINIMAL`; frozen negative vector `conformance/scb1/v1/rejected.json`). Every envelope below reads its version/tag/length through that reader or an equivalent local `Reader` that emits the same code (`crates/sley-state-root/src/lib.rs:781`, `crates/sley-policy/src/lib.rs:2473`).
- Every envelope decoder checks `is_finished`/`check_finished` after the trailer, so trailing bytes fail as `SCB_TRAILING_BYTES` before any digest is exposed.

Evidence notes:

- R (recursion): every SCB1-enveloped identity places its trailer outside the preimage (lib.rs:566-567, exchange.rs:636-637, merge.rs:2147-2149, compare.rs:1269-1271, protocol lib.rs:1112-1121; specs say "trailer is outside its own preimage"). Pack and exchange leaves hash contained stored bytes including the contained objects' own trailers, which is intended (an object's trailer is its ObjectId, verified separately at lib.rs:878-885) and not self-referential. Capsules embed the exact response record, which carries no capsule id. Snapshot admission compares the trailer to the id of the preimage (snapshot.rs:744).
- I (inclusion/exclusion): pack fields 4, 6, 9 must be empty/absent (lib.rs:692-698); exchange field 8 must be union tag 0 (spec Payload table); GC witness, index cache, staged files are excluded by construction (exchange.rs:65-70). Branch records exclude the path key (NATIVE_REFS section 3). Nothing optional is silently omitted: SCB1 options use explicit union tags; query-family options use u32be(1)/u32be(2).
- F (field order): SCB1 records require strictly increasing tags (RecordReader, lib.rs:676-686); query-family preimages are positional with fixed order in one encoder function each.
- L (length): every variable-length component is length-prefixed (SCB1 Bytes/lists; pack/exchange leaf `uvar(len(bytes))` lib.rs:922-931, exchange.rs:849-857; capsule `u64be(len(record))` capsule.rs:452, context capsule `u64be(response_bytes)` :601 with the builder refusing a length mismatch; adapter Encoder::bytes u64be length :1275). ProtocolHandshakeId (OK*): the transcript concatenates three variable-length records with no length words (lib.rs:715-727); uniqueness rests on each hello body and the selection being one complete canonical SCB1 record, which a prefix parser delimits deterministically, and on both peers hashing the observed bytes. No ambiguity is demonstrable; the spec (SMP1.md section 2) does not state this argument.
- D (domain separation): all identities carry a distinct `sley2.*` domain, and framing magic differs per family (SLEYBR01/SLEYRF01/SLEYBNM1, SLEYQRY1/SLEYRQQ1/SLEYRQC1/SLEYCCP1/SLEYIDX1, SLEYADS1/SLEYADT1). Pack and exchange leaf/node use separate domains from each other and from the outer ids.
- U (domain reuse): IndexSnapshotId (OK*) uses one domain for arm 1 and arm 2 records; the arm is bound inside the preimage (snapshot.rs:557) and consumers reject the wrong arm (COMPLETE_ROOT_INDEX_SNAPSHOT_PROFILE_V1.md lines 50-55, snapshot.rs:1387). No cross-object reuse. See finding CF-1 for the digest_domain_tag integers.
- B (dependency binding): pack binds contained epochs, roots, objects and its own descriptor hashes through the epoch id; exchange binds pack, receipts, branches, head; conflict binds both delta ids and all three roots; delta binds both roots, workspace and root epoch; capsules bind root, epoch, workspace, snapshot, query id, and (context capsule) session; session binds handshake, workspace, root, epoch; transcript binds epoch, root, pre and post state. Restricted QueryId binds a claimed root only optionally, by contract (RESTRICTED_QUERY_PROFILE_V1.md section 4: "not proof of root provenance").
- S (schema/profile binding): SCB1 identities bind the per-contract conformance epoch whose descriptor commits field_schema_hash and decoder_limits_hash (lib.rs:1376-1385, merge.rs:58-65, compare.rs:52-59); IndexSnapshotId binds SSMC1_FIELD_SCHEMA_HASH and limits_profile (snapshot.rs:548-549); query family binds format_version, profile_version, limits_profile; frame binds protocol epoch; adapter ids bind profile_version and abi.
- P (platform): all integers are explicit big-endian or uvar (query.rs:897-901, capsule.rs:508-513, snapshot.rs:884-889, context_capsule.rs:669-675, adapter :1267-1273, session.rs:185); lengths pass through u64 conversion; no usize, pointer, or endian-native bytes enter any preimage.
- M (map/set order): pack and exchange decoders reject unsorted or duplicate entries (PACK_CANONICAL_ORDER, EXCHANGE_CANONICAL_ORDER; exchange.rs:3115 test; rejected fixture reversed-branches); delta/conflict use require_sorted (compare.rs:1281-1289); branch dependency roots strictly sorted (refs.rs:2158-2163); snapshot inventory and edges are raw-id ordered and the reverse groups are recomputed and compared (snapshot.rs:742); adapter maps use BTreeMap order with canonical-key checks (spec section 6).
- N (Unicode): branch names are ASCII lowercase only with no normalization (refs.rs:435-446), so NFC does not apply; adapter virtual paths and environment keys are checked for canonical form before hashing (REFERENCE_ADAPTER_PROFILE_V1.md section 6). No other identity in this group hashes text.
- W/G (width/signedness): all counts are u64 and all tags u32 in fixed-width or uvar form; no signed integers appear in any preimage in this group.
- T (trailing bytes): outer envelopes reject trailing bytes in code (lib.rs:666-669, exchange.rs:668-673, merge.rs:2191-2194, compare.rs:1361-1364, protocol decode_frame requires envelope.len() == length :1146-1149; snapshot cursor.finish :741). Negative evidence: pack has a Python-verified `trailing-byte` fixture but no Rust unit test; exchange (OK*) has neither a fixture nor a Rust test for an outer trailing byte (only a nested receipt trailing byte, exchange.rs:3019); merge and delta have both (merge.rs:2779-2782, compare.rs:2455-2459 plus fixtures); protocol has truncated-envelope and a flipped-trailer but no explicit extra-byte case (the length prefix check covers it). Query-family requests are not stored envelopes (na); IndexSnapshot admission rejects insertions (snapshot.rs:1190-1195).
- C (noncanonical): non-minimal varints rejected in the pack/exchange reader (lib.rs:1127-1148, tested lib.rs:1404) and protocol reader (lib.rs:1501-1519, final zero group rule); fixed-width fields in the query family leave no alternate encoding.
